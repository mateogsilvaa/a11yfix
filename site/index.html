Accessibility fixes that prove themselves.

verifa11y finds WCAG violations in your HTML, writes the smallest fix for each and re-checks the page in a real browser. A fix that only silences the checker is thrown out, and you're told why.

What it's for

A quiet checker is not a fixed page.

Coding agents fix accessibility by the hundred, and most confirm it by re-running a checker. But hide the element, add a generic label or restate the file name, and the checker goes quiet. verifa11y keeps a fix only if it survives checks a silenced violation can't pass.

Rejected: alt="plot map" only restates the file name

  1. 01 · Audit

    Find every violation, to the line.

    verifa11y opens the page in headless Chromium and runs axe-core. Each violation is pinned to the exact line in your source file.

  2. 02 · Patch

    Write the smallest fix.

    A codemod fixes what the markup can prove: a misspelled role, a skipped heading. The image needs judgment, so here a quick fix guesses. With a model configured, your model writes it instead.

  3. 03 · Shape

    Nothing invented gets through.

    Every patch must quote your file exactly and stay small: at most 6 lines and 2 hunks.

  4. 04 · Copy

    Your file stays put.

    Patches go onto a copy that renders exactly like the original. Page scripts never run, and requests to other sites are blocked.

  5. 05 · Verify

    Six checks per patch.

    The role and the heading pass all six. The alt text passes axe, then fails two checks: it only restates the file name. Rejected.

  6. 06 · Review

    You decide what ships.

    One .patch with the fixes that held up, and a report of everything rejected or skipped, with the reason.

The verifier

Six checks. None of them trusts the patch.

Each one catches a way of making a violation disappear without fixing it. Same rules for every patch, including verifa11y's own.

  • image-alt 1 0new violations 0

    Gone, and nothing new

    axe-core with every WCAG 2.x A/AA rule, on the whole page.

  • <img aria-hidden="true">rejected

    Nothing hidden

    No aria-hidden, role="presentation", inert, display:none or deleted elements.

  • alt="plot map"= plot-map.png

    Names that mean something

    No “image”, no alt that restates the file name, no label that restates the field's name.

  • mainnav · navigationimg · "plot map"button · Join

    Accessibility tree

    Chromium's computed role, name and state of every element, before and after.

  • 1234

    Focus order

    Real Tab presses, before and after. Nothing may leave the tab order or reorder.

  • 0.00% outside

    Pixels and references

    Nothing outside the patch changes on screen; every aria-controls points at something real.

What no check can tell you: whether alt text describes what an image is for, whether a state is true, whether a colour fits your design, or the large part of WCAG that isn't machine-testable. Every patch still goes to a person.

Read the naive rows carefully

The naive fixer gets more patches past the verifier than the codemods do, and many would fail a review: invented state, inline colour overrides, a live region deleted. None makes the page worse, which is what a verifier can prove. “Verified” is an upper bound, not a grade.

FAQ

Before you try it.

Does verifa11y make my site accessible?

No. It fixes specific, machine-detectable violations and proves those fixes didn't make anything worse. Most of WCAG can only be judged by a person. Treat it as a fast, careful first pass, never as a certificate.

Does my code leave my machine?

Only if you configure a model or agent for the fixes that need judgment; then the page goes to whatever you configured. No telemetry, no account, no server. Pages render offline.

Do I need an AI model?

No. Codemods fix what can be proven from the markup (misspelled roles, invalid ARIA values, heading levels, simple labels) and the rest is reported as skipped. With a model it also attempts alt text, contrast and widget state.

Which rules does it patch?

image-alt, label, heading-order, aria-allowed-attr, aria-required-attr, aria-valid-attr-value, aria-roles and color-contrast. The verifier checks every WCAG 2.x A/AA rule axe-core has.

What about React, Vue or a live site?

Patching works on static HTML today; frameworks are on the roadmap. verifa11y site audits a live site but only reports: a live page has no source file to patch.

How is “verified” different from “passes axe”?

Passing axe means the rule stopped reporting. Verified also means nothing new broke, nothing was hidden, no name became meaningless, and the accessibility tree, focus order and pixels still agree. On the benchmark, 238 patches pass axe and fail the rest.

Is it free?

Yes. Apache-2.0, on GitHub. Bug reports and contributions welcome.

Install

Pick where you work.

Node.js 20 or later. No model needed: verifa11y applies the fixes it can prove and tells you why it skipped the rest.

Claude Code

  1. Install the browser verifa11y renders with, once.

    npx verifa11y-mcp --install-browser

  2. Add the MCP server to your project.

    claude mcp add verifa11y -- npx -y verifa11y-mcp --root .

  3. Ask for it in plain words, for example:

    Fix the accessibility of index.html with verifa11y.

  4. Claude gets a patch under .verifa11y/, never an edited file. Review the diff, then git apply it.

Terminal

  1. Install the browser, once.

    npx verifa11y install-browser

  2. Audit a page. Every violation, with its rule, WCAG criterion and source lines.

    npx verifa11y audit page.html --out findings.json

  3. Fix and verify. Only patches that pass all six checks make it into the output.

    npx verifa11y fix findings.json --verify --strict --out patches

  4. Read the report, then apply what you agree with.

    git apply patches/verifa11y.patch

  5. Optional: let any model or agent CLI write the fixes that need judgment. Its patches face the same checks.

    npx verifa11y fix findings.json --verify --strict --generator-cmd "claude -p"

Cursor, Codex, any MCP host

  1. Install the browser, once.

    npx verifa11y-mcp --install-browser

  2. Add the server to your host's MCP configuration (Cursor's .cursor/mcp.json, Claude Desktop's config, and so on).

    {
  "mcpServers": {
    "verifa11y": {
      "command": "npx",
      "args": ["-y", "verifa11y-mcp", "--root", "."]
    }
  }
}

  3. The agent gets four tools: rules, audit, fix and verify. Every result says what was verified and that a person must review it.

GitHub Actions

  1. Add a workflow. On every pull request it audits the HTML that changed.

    name: accessibility
on:
  pull_request:
    paths: ["**/*.html"]
permissions:
  contents: read
  pull-requests: write
jobs:
  verifa11y:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          ref: ${{ github.event.pull_request.head.sha }}
          persist-credentials: false
      - uses: actions/setup-node@v4
        with: { node-version: 22 }
      - uses: mateogsilvaa/verifa11y@v0.4.1

  2. Verified fixes arrive as suggestions on the exact lines. Suspicious and skipped findings are listed for a person, never suggested.
