# verifa11y 0.4.0

**a11yfix is now verifa11y.** Same project, a name nobody else uses, and one that says what sets it apart: every
patch is verified, including our own. Details and the full list of renamed commands, packages and variables in
[ADR 0018](https://github.com/mateogsilvaa/verifa11y/blob/v0.4.0/docs/adr/0018-rename-to-verifa11y.md).

This release measures the verifier instead of only trusting it.

## Highlights

**What the verifier catches, and what it cannot.** A deliberately naive fixer (alt text from the file name,
`aria-label` from the field's `name`, remove whatever axe complains about) now runs through the same pipeline,
offline. On the 22 dev pages the full verifier rejects 250 of its 653 patches that a pipeline without it would have
shipped as fixed; re-running axe alone would have let 223 of them through. It also still verifies 403 naive patches,
many of which a reviewer would reject (invented widget state, inline colour overrides). The report says so, rule by
rule: precision against the verifier is an upper bound, not a grade.

**Two gaps closed.** The naive baseline found two kinds of bad patch the verifier could reject without judgment, and
now does: an `aria-label` that only restates the field's `name` or `id`, and an id reference that points at nothing
(`aria-controls="false"`). No tier-0 patch is affected.

**A held-out corpus.** 73 new pages (Start Bootstrap templates, Bootstrap examples, MDN accessibility pages, axe-core
fixtures), each with its source and license, that nothing is tuned on. Reports show eval and dev separately, with 95%
Wilson intervals and n everywhere. Tier 0 on eval: 18 of 18 verified, 100% [82.4–100]. Honest caveat: most eval
violations are `color-contrast`, which tier 0 does not touch, so its eval sample is small.

**A GitHub Action.** On a pull request it audits the HTML that changed and posts verified fixes as suggestions on the
exact lines, codemods only unless you name a model. Suspicious, rejected and skipped findings go in the review body,
never as suggestions. Read-only on forks (job summary instead). See
[docs/github-action.md](https://github.com/mateogsilvaa/verifa11y/blob/v0.4.0/docs/github-action.md). It has passed
its tests; this is its first release, so report anything odd.

**The README shows it working**: an animated demo recorded from real runs, the results table with the uncomfortable
rows, and a real rejected patch with its reason.

## Breaking changes

- Command `a11yfix` → `verifa11y`; MCP server `a11yfix-mcp` → `verifa11y-mcp`; packages `a11yfix-*` → `verifa11y-*`.
- Environment variables `A11YFIX_*` → `VERIFA11Y_*`.
- Output names: `a11yfix.patch` → `verifa11y.patch`, `.a11yfix/` → `.verifa11y/`, `a11yfix.sqlite` →
  `verifa11y.sqlite`.
- The two new checks can reject patches that 0.3 verified.

No aliases for the old names: nothing was published under them.

## Not in this release

- Numbers for a real model (tier 1). The benchmark is ready (`npm run bench`, or `--generator-cmd` for any model);
  it has not been run.
- npm packages. Install from the repository for now (see the README).

verifa11y does not guarantee WCAG conformance. "Verified" means the automatic checks found the violation gone and
nothing else worse; every patch still needs a person to review it.
