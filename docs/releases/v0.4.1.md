# verifa11y 0.4.1

verifa11y is ready for npm. Nothing changes in how pages are audited, patched or verified.

```sh
npx verifa11y install-browser       # once: the headless Chromium it renders with
npx verifa11y audit page.html --out findings.json
npx verifa11y fix findings.json --verify --strict --out patches
git apply patches/verifa11y.patch
```

For AI agents, the MCP server: `claude mcp add verifa11y -- npx -y verifa11y-mcp --root .` (any MCP host: command
`npx`, arguments `-y verifa11y-mcp --root <project>`).

## What's new

- **npm packages**: `verifa11y` (CLI), `verifa11y-mcp`, `verifa11y-core`, `verifa11y-rules-core`.
- **`verifa11y install-browser`** (and `verifa11y-mcp --install-browser`) installs exactly the Chromium the bundled
  Playwright expects; `--with-deps` adds the system libraries on Linux.
- A missing browser now gives a one-line fix instead of a stack trace.

The highlights of 0.4.0 (the rename, the naive baseline, the held-out corpus, the GitHub Action) are in the
[0.4.0 notes](https://github.com/mateogsilvaa/verifa11y/releases/tag/v0.4.0).

verifa11y does not guarantee WCAG conformance. "Verified" means the automatic checks found the violation gone and
nothing else worse; every patch still needs a person to review it.
